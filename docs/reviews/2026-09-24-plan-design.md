## Findings (raw)

## Findings

1. **High — M1 can hide the information needed to finish a task.** A teammate posts a 6,000-character result with the decisive detail near the end. M1 clips it to 2,000 characters and tells the next bot to use `thread_read`, but that tool does not arrive until M4. A fresh or non-MCP bot cannot recover the detail and may give the wrong answer. This also affects long code fences and notices. [Plan §3.1](docs/plans/lean-runtime.md:87), [M1](docs/plans/lean-runtime.md:273). **Smallest fix:** ship `thread_read` before clipping, or retain full relevant messages until it is available.

2. **High — M1 removes a working delegation path two milestones early.** In a direct chat, a manager can currently delegate to a direct report using an `anybot` block. M1’s “@mentions only” direction cannot replace that: mentions activate project members, while direct reports may be outside the conversation. The `handoff` MCP tool is scheduled for M4. [Coordinator `prompt()`](runtime/coordinator.mjs:1165), [`delegate()`](runtime/coordinator.mjs:1560). **Smallest fix:** keep and document block-based direct-report delegation until `handoff` works for that harness.

3. **High — the proposed session delta includes future assignments.** Today `prompt()` deliberately excludes human assignments submitted after the queued run’s assignment, while admitting eligible replies from earlier runs. If a bot is queued for message A, the owner sends unrelated message B, and A then starts, the proposed `rowid > last_message_rowid` query sends B to the bot answering A. It can work on the wrong request or answer both. [Coordinator `prompt()`](runtime/coordinator.mjs:1114), [plan §3.2](docs/plans/lean-runtime.md:126). **Smallest fix:** apply the current assignment cutoff and response eligibility to session deltas; test a later human message arriving while a run waits.

4. **High — a session cursor can silently lose context after a failed turn.** The plan records the newest included rowid after a run, but does not define when that update commits. A harness can accept the prompt, change files, then fail or be cancelled. Advancing the cursor loses those messages on retry; retaining it while resuming the partially advanced CLI session duplicates them. [Plan §3.2](docs/plans/lean-runtime.md:126), [Coordinator `execute()`](runtime/coordinator.mjs:1512). **Smallest fix:** commit session ID and cursor only on a confirmed successful turn; invalidate the session after cancellation, interruption, or ambiguous failure, and use fresh mode for the next run.

5. **High — “pointers instead of bodies” can drop unread reports.** `orgContext()` currently marks reports read when it places their summaries in the prompt. M4 proposes a pointer such as “2 unread reports” in place of the bodies. If that path still calls `markRead`, the bot may never fetch them and they disappear from its unread set. [Coordinator `orgContext()`](runtime/coordinator.mjs:1184), [plan §3.4](docs/plans/lean-runtime.md:207). **Smallest fix:** mark each report read only when its content is delivered in a prompt or successful MCP read.

6. **High — M3’s windowed snapshot breaks current renderer views.** After 100 newer messages, an older thread root falls outside `data.messages`; `App.jsx` can no longer find that root to open its thread. The unread calculation also treats a saved last-seen ID outside the window as missing, so old replies can appear newly unread. Activity resolves assignment text through `data.messages`, and it reads `run.output` for live status. [Plan §3.3](docs/plans/lean-runtime.md:164), [App thread and unread logic](src/App.jsx:386), [Activity](src/App.jsx:1560). **Smallest fix:** provide thread-root and assignment summaries plus a server-side unread cursor, and migrate every renderer consumer before shrinking the snapshot.

7. **High — in-memory-only streaming loses partial output on interruption.** If a bot emits useful work and then the worker crashes, the app restarts with runs marked `interrupted`; M3’s output buffer has vanished, and its “write once, at the end” step never happened. Today `execute()` periodically saves partial output. [Plan §3.3](docs/plans/lean-runtime.md:168), [Coordinator `execute()`](runtime/coordinator.mjs:1363), [restart recovery](runtime/coordinator.mjs:147). **Smallest fix:** checkpoint partial output periodically or durably append it to the terminal log and expose it on interrupted runs.

8. **High — the delta recovery contract is underspecified across worker restarts.** Main retains 500 changes, but the worker owns state and can restart. A delayed delta or `sync.since` reply from the old worker can be applied after the new worker’s snapshot if sequence numbers alone identify updates. Posting a delta before a command reply also does not prove that the renderer has applied it before `act()` continues. [Plan §3.3](docs/plans/lean-runtime.md:161), [main worker supervision](desktop/main.cjs:925), [App `act()`](src/App.jsx:353). **Smallest fix:** add a worker epoch to snapshot, delta, and reply; clear main’s ring on restart; make command resolution wait for reducer application of its sequence.

9. **High — the mobile gateway cannot simply keep its response shapes after M3.** It currently fetches a full snapshot for each authenticated request, filters `state.messages` for a conversation, and pages that array. A windowed snapshot makes older mobile pages unavailable and can make a valid `before` cursor look invalid. [Gateway `handle()`](runtime/mobile-gateway.mjs:315), [conversation paging](runtime/mobile-gateway.mjs:396). **Smallest fix:** move gateway paging to a scoped `messages.page` query before changing `snapshot()`.

10. **High — workspace settings as an MCP fallback can leak the run token.** M4 proposes writing and removing workspace settings around Gemini or Cursor runs. A settings file in a project can be read by another process or bot, picked up by a git add, or left behind after a crash; concurrent runs may overwrite or remove each other’s settings. The existing approval bridge instead writes a per-run config outside the workspace. [Plan §3.4](docs/plans/lean-runtime.md:201), [`Approvals.register()`](runtime/approvals.mjs:61). **Smallest fix:** require verified per-run config outside the workspace; keep those harnesses in fenced-block mode if they cannot accept it.

11. **High — CLI availability is treated as MCP availability.** If Codex starts with an unreachable MCP server, its adapter currently treats some pre-turn error events as warnings and carries on. M4 would omit the action guide and replace task context with tool pointers, leaving a bot with no usable tool and too little context. Cursor is uninstalled here, and the plan itself calls Gemini/Cursor settings support a spike. [Adapter `extractEvent()`](runtime/adapters.mjs), [plan §3.4](docs/plans/lean-runtime.md:201). **Smallest fix:** verify tool registration for the actual run before selecting the MCP prompt variant; fail or retry fresh with full context when registration fails.

12. **Medium — the code-review checkpoint uses an unsupported command shape.** The protocol passes a prompt on stdin to `codex review --base main -`. The checked CLI fact supports `codex review --base <branch>`; the trailing `-` stdin contract belongs to `codex exec resume`, not the stated review command. M0’s required review script may fail before any review occurs. [Plan §7](docs/plans/lean-runtime.md:410). **Smallest fix:** use `codex review --base main` for diff review, or use `codex exec --sandbox read-only -` when a custom stdin prompt is required.

13. **Medium — several exit gates cannot be met or interpreted as written.** A single allowed 24,000-character message can exceed M3’s 2 KB streaming-tick limit, and 100 messages can exceed its 64 KB snapshot limit. The M2 “input tokens drop ≥50%” gate mixes Any Bot prompt savings with harness tool calls and provider caching; a correct implementation can fail it. [Input limit](runtime/coordinator.mjs:996), [M2 gate](docs/plans/lean-runtime.md:292), [M3 gate](docs/plans/lean-runtime.md:327). **Smallest fix:** define percentile and fixture-specific byte gates, allow bounded chunking, and measure harness input tokens on a controlled task with separate cached-token accounting.

**What holds up:** the stated Claude and Codex resume forms match the supplied CLI facts; serializing runs by employee and workspace in `dispatch()` supports separate per-thread sessions without concurrent use of one bot’s session.

**Three changes first:** move recoverable context access and direct-report handoff ahead of prompt removal; specify session cursor commit and failure rules using the current assignment cutoff; make M3 paging and durable partial output work across desktop, mobile, and worker restart before enforcing byte budgets.
