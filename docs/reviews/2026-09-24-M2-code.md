## Findings

1. **High — Restart can resume a session that absorbed an interrupted turn.** If turn 1 succeeds, turn 2 resumes that session, and the app exits while turn 2 is running, startup marks turn 2 `interrupted` but leaves the session row. Turn 3 can then resume a native history containing part of turn 2 while Any Bot’s delivered set says otherwise. [coordinator.mjs](<runtime/coordinator.mjs:167>)  
   **Smallest fix:** Delete sessions for runs found running or cancelling at startup. **Test:** Reopen a database containing a saved session and an interrupted run for its key; assert the next run starts fresh.

2. **High — “Start fresh” and bot archive can be undone by an in-flight run.** Drop a session while its bot is running; when that run succeeds, it saves the session again. Restoring an archived bot can therefore resume history that archive was meant to invalidate. A late failure from a force-cancelled run can also delete a newer run’s session for the same key. [coordinator.mjs](<runtime/coordinator.mjs:1645>)  
   **Smallest fix:** Give each session key an invalidation generation and save or drop only if the run still owns that generation. **Test:** Hold a runner open, invoke `sessions.startFresh` or archive, release it, and assert no session returns; also settle an old cancelled run after a replacement succeeds.

3. **Medium — Teammate edits leave stale instructions in native history.** The stable team and delegation layers include teammate names and roles, but the policy hash contains only member IDs. Rename a teammate or change their role, then run the bot again: it resumes with the old roster and receives no updated stable layer. [sessions.mjs](<runtime/sessions.mjs:36>)  
   **Smallest fix:** Hash the names and roles used to build those layers. **Test:** Change a teammate’s name or role between turns and assert a fresh invocation with the new roster.

4. **Medium — Messages omitted by the fresh prompt are permanently marked delivered.** A fresh turn can trim older history to its budget, yet `seen` records every queried message ID. A later resumed turn skips those IDs even if its assignment now makes one of those messages relevant. [context.mjs](<runtime/context.mjs:170>)  
   **Smallest fix:** Record IDs actually rendered into the prompt, and retain the existing budget rules when selecting later history. **Test:** Omit an older teammate message on turn 1, name that teammate in turn 2, and assert the resumed prompt includes the message.

**Must block merge:** Findings 1–4. Resume is off by default, but these defects break the M2 path when enabled; findings 1, 2, and 4 can silently diverge from or skip conversation history.

## Triage

Every finding gets a verdict. High and critical findings are fixed, or rejected with evidence, before merge.
