## M2 review findings

1. **Critical — the migration number is already taken.** The plan calls `harness_sessions` “schema v15,” but [store.mjs](runtime/store.mjs:8) already sets `SCHEMA_VERSION = 15` and uses v15 for usage metrics. An existing v15 database would skip a new migration guarded by “version < 15”; session lookup would then fail because the table does not exist. **Smallest fix:** make sessions v16 and add a v15-to-v16 migration test.

2. **Critical — direct chats can acquire multiple session rows.** The proposed primary key includes nullable `thread`. In SQLite, `NULL` values in a composite primary key do not identify one unique row. Two successful direct-chat turns can therefore create separate rows for the same bot and conversation; a later lookup can resume the wrong session or fail to find a reliable cursor. **Smallest fix:** store a non-null thread key, such as `''` for direct chats, and make all key columns `NOT NULL`.

3. **High — “newest included rowid” can skip an eligible message forever.** The [plan’s cursor rule](docs/plans/lean-runtime.md:170) allows an earlier assignment’s reply to arrive after a later human message. For example, run A’s assignment is row 10, another human’s project message is row 11, and a reply to an earlier assignment is row 12. A may include row 12 while excluding row 11, then commit cursor 12. When the bot is next addressed, `rowid > 12` cannot deliver row 11. [promptParts()](runtime/coordinator.mjs:1160) permits precisely this out-of-order inclusion. **Smallest fix:** track delivered message IDs, or advance a contiguous eligibility watermark only when no earlier undelivered row remains.

4. **High — channel background bypasses the stated eligibility rule.** [promptParts()](runtime/coordinator.mjs:1183) bounds channel roots to before the thread root, but fetches each root’s *latest* reply without an assignment-row boundary. A human can post a reply in another thread while this run waits; the queued run then sees it in channel background even though §3.2 promises that later human input is excluded. A delta implementation could also resend old background or omit new eligible background because it is outside the main message cursor. **Smallest fix:** apply the same per-run cutoff and delivery tracking to channel replies, and test that path separately.

5. **Critical — changed permissions and instructions remain in native history.** §3.2 invalidates for harness, model, workspace, and removal, but [employee edits](runtime/coordinator.mjs:552) can change instructions and permission mode, and [project settings](runtime/coordinator.mjs:687) can change allowed folders. Merely prepending “Updated instructions” leaves the old instructions and formerly supplied file paths inside the resumed CLI session. A bot can continue using stale authority or stale project facts. **Smallest fix:** rotate the session on any execution-policy, instruction, audience, or allowed-folder change; reserve in-session updates for harmless context.

6. **High — the fresh retry needs a pre-turn failure boundary.** [runHarness()](runtime/adapters.mjs:724) currently turns structured errors and nonzero exits into general failures. If a resumed CLI starts executing, edits files, then emits an error mentioning an invalid session, §3.2’s automatic fresh retry can repeat those edits. **Smallest fix:** retry only on a typed, verified resume rejection received *before* `turn.started` or any tool activity. Otherwise mark the run failed and require reconciliation.

7. **High — the Codex resume command drops current run controls unless explicitly rebuilt.** The proposed `exec resume <id> -` is only a skeleton. Fresh Codex runs currently pass `--json`, `--skip-git-repo-check`, and `--sandbox workspace-write` in [invocation()](runtime/adapters.mjs:436); [runHarness()](runtime/adapters.mjs:714) depends on structured JSON events for text, errors, and usage. A bare resume command could produce unparsed output or run with different controls. **Smallest fix:** define and test a complete resume argv for each harness, including model, output format, sandbox, and approval settings. Claude’s local `--resume` flag was visible in `--help`; local Codex `--help` returned “Access is denied,” so its exact resume argv remains unverified here.

8. **Medium — the size gate conflicts with the current layer layout.** [buildContext()](runtime/context.mjs:121) puts the *current run’s supplied file list* in layer 4. That list can change each turn, forcing the preamble hash to change and layers 1–4 to be resent. The [15% gate](docs/plans/lean-runtime.md:401) can fail on ordinary attachment turns even when session resume works. **Smallest fix:** move supplied file paths to layer 6; keep only the stable artifact contract in layer 4.

9. **Medium — the live token gate cannot be read directly from the stored usage field as written.** The plan specifies Claude’s raw `input_tokens` as uncached input, while [readUsage()](runtime/usage.mjs:30) stores a normalized input total that adds cache reads and cache creation. Reading `runs.usage` as if it were Claude’s raw field would give the wrong comparison. **Smallest fix:** define the gate against recorded raw usage components, or calculate uncached input from the normalized stored fields consistently for both harnesses.

The current dispatcher does serialize runs for one employee and one workspace, and it builds prompts when execution starts; those parts support the queued-turn and per-session ordering assumptions in M2. [dispatch()](runtime/coordinator.mjs:1297)

**First three changes:** assign schema v16 with a non-null session key; replace the single rowid cursor with delivered-message tracking across both thread and channel context; rotate sessions on policy changes and permit fresh retry only for a verified pre-turn resume rejection.

## Triage

Every finding gets a verdict. High and critical findings are fixed, or rejected with evidence, before merge.

| # | Finding | Severity | Verdict | Evidence |
|---|---|---|---|---|
| 1 | Schema v15 is already taken by usage metrics | critical | Accepted | `harness_sessions` is schema v16, with a v15 → v16 migration test. |
| 2 | Nullable `thread` in the primary key lets direct chats get several rows | critical | Accepted | `thread TEXT NOT NULL` (`''` for direct chats); every key column NOT NULL. Test: two direct-chat turns leave one row. |
| 3 | A single rowid cursor can skip a message delivered out of order | high | Accepted | Delivered-message tracking (`harness_session_messages`) replaces the cursor: the delta is today's eligible set minus what the session already got. Test with Codex's row 10/11/12 sequence. |
| 4 | Channel background skips the per-run cutoff and the delta | high | Accepted | Background replies are bounded by the assignment's rowid (fresh and resumed), and background messages count as delivered like any other. Test: a human reply posted in another thread while the run waits is not shown. |
| 5 | Changed instructions or permissions stay in the resumed native history | critical | Accepted | No "Updated instructions" path. A policy hash (harness, model, workspace, permission mode, instructions, name, allowed folders, members) is stored per session; any change rotates to a fresh session. Test per trigger. |
| 6 | Fresh retry could repeat work if the error came mid-turn | high | Accepted | Retry only on a typed `ResumeRejected` recognized **before the turn starts**: Claude `result` with `is_error`, `num_turns: 0` and "No conversation found with session ID", before any assistant event; Codex exit ≠ 0 with no JSON event and "no rollout found" / "thread/resume failed" on stderr (both captured live). Anything else fails the run normally and invalidates the session. |
| 7 | Resume argv must carry every run control | high | Accepted | Full argv per harness: Claude keeps model, permission flags, MCP config, `--output-format stream-json --verbose`, plus `--resume <id>` (fresh turns pass `--session-id <uuid>`); Codex `exec resume --json --skip-git-repo-check -c sandbox_mode="workspace-write" [-m model] <id> -` (`exec resume` has no `--sandbox`, verified live). Fake-CLI tests assert the argv. |
| 8 | Per-run file list in the stable layers breaks the preamble | medium | Accepted | The supplied-files list moves to a per-turn `files` section; the artifacts contract stays stable. |
| 9 | Live token gate vs normalized usage | medium | Accepted | The gate is computed from stored fields for both harnesses: uncached = `input_tokens − cached_input_tokens` (both normalized). Plan text fixed. |
