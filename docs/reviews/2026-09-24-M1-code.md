## Findings (raw)

1. **High — A referenced teammate report can disappear from the prompt.** If Sam posts a 6,000-character report, the owner then posts 8,000 characters, and Alex later asks to review “Sam’s report,” the newer owner message consumes the optional history budget. The report is omitted even though the assignment names Sam. I reproduced this with `buildContext`: the prompt says one earlier message was not shown. [context.mjs](runtime/context.mjs:169). **Smallest fix:** reserve or include assignment-referenced messages before filling the optional budget, with a separate allowance if necessary. **Test:** put a named 6,000-character report behind an 8,000-character older owner message and assert the report arrives whole.

2. **High — History hygiene removes an owner’s code example from a mandatory thread root.** If the owner posts a fenced `anybot-actions` example and later asks a bot to review that example, the root is present but its fenced contents are stripped. The bot cannot inspect what it was asked about. I reproduced this in the root section. [context.mjs](runtime/context.mjs:139). **Smallest fix:** strip only machine blocks known to have been applied from bot responses; preserve owner-authored examples. **Test:** ask about an `anybot-actions` block in a human thread root and assert the block reaches the bot.

3. **High — Quoted code can still start a bot.** A response containing `~~~js` followed by `@Alex run this` activates Alex because the new filter recognizes backtick fences but not tilde fences or indented code. I reproduced both forms with `mentionedIds`. This can queue an unintended CLI run from example text. [mentions.mjs](runtime/mentions.mjs:12). **Smallest fix:** recognize Markdown tilde fences and indented code before scanning for mentions. **Test:** assert mentions inside each form do not produce recipients.

**Must block merge:** all three findings.
